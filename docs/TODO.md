## Расширение алгоритмов сжатия контекста диалога

Статус: запланировано; базовое сжатие результатов инструментов (`compactToolMessage`, `compactAssistantMessage`, кнопка «Compact context») реализовано.

### Мотивация

Текущая реализация `compactContext` заменяет вывод завершённых инструментов (`read_file`, `list_dir`, `find_files`, `get_file_structure`, `git`, `grep`) и большие тела `write_file` на компактные заглушки с числом прочитанных строк или изменённых файлов. При длинных сессиях и сложных многошаговых задачах этого становится недостаточно: реплики пользователя и ассистента накапливаются, съедая окно контекста модели.

### Задачи на будущее

1. **LLM Rolling Summarization (Сжатие истории диалога через модель)**:
   - При превышении порога контекста (например, > 80%) или по нажатию кнопки «Compact context» отправлять запрос к модели для краткого структурированного саммаризации ранних раундов (turns) разговора:
     - Какие задачи ставились;
     - Какие ключевые файлы были изменены;
     - Какие архитектурные решения приняты.
   - Заменять старые сообщения `user` и `assistant` на единое системно-структурированное сообщение `[Previous conversation summary]`, сохраняя последние N ходов нетронутыми.

2. **Локальный эвристический / семантический анализатор контекста**:
   - Анализ зависимостей между вызовами инструментов:
     - Если файл был прочитан (`read_file`), а затем полностью перезаписан (`write_file`), ранний вывод `read_file` и промежуточные diff'ы можно безопасно отбрасывать.
     - Если один и тот же файл читался повторно без изменений, сохранять только последнее чтение.
   - Дедупликация и сжатие повторяющихся результатов `list_dir` / `find_files` / `get_file_structure` при отсутствии изменений в файловой структуре.
